# SK1-QUILL-DIAG-PUB-T-968 — проверка FD-предсказания на новых PUB

[Постановка задачи в Notion](https://app.notion.com/p/3f532a84beec81fe9ecde7315269c743).

**Вопрос:** предсказывает ли только исходная структура Quill попадание позиции вставки +1 ASCII в существующую границу FDPP/FDPC, и совпадает ли это с точным машинным отказом `quill_insertion_at_fd_boundary` закреплённого Writer?

**Отделение от прежних опытов:** T958 изучал обратную вставку после удаления на прежних PUB, T966 наблюдал 10 отказов в новых позициях прежнего корпуса, T967 предсказывал максимальную длину роста на заранее допустимых позициях старых 14 файлов. Здесь только заранее выбранные НОВЫЕ SHA и классификация локального FD-гейта из исходных байтов.

## Предрегистрация: отдельный корпус

- Исходный каталог: `Lalalalendia/lalamu@f78cc6f455f4dc222868f9cc035511a6ca7a91ea`, 370 исходников. Фильтр HTTPS, ровно `.pub`, проверка size + SHA-256 + CFB.
- Полностью исключены исходные **35 SHA** EXP001–004 и **62 SHA** EXP005. Не включать исходники из T959/T962/T966/T967 — они уже входят в 62.
- Детерминированный список из **27 новых SHA** в фиксированных квотах: mathematicshed **16**, storage.googleapis **3**, cmapspublic2.ihmc.us **5**, ci.king.nc.us **3**. Берутся лексикографически первые SHA из оставшихся допустимых строк каждого разрешённого хоста. Входные URL нигде не печатаются.
- До 3 обычных Story исходного Editor и уникальные first, second, middle, last UTF16-позиции буквы/цифры (максимум 12 attempts/PUB). Совпадения физического смещения не считаются новым случаем. Каждое редактирование заново из оригинала.

## Слепая структурная метка и контроль

**До первого вызова Writer** исходный Quill разбирается фиксированным `pub_quill::parse_confirmed_story_catalog`; из FDPP/FDPC дескрипторов отдельно извлекаются все абсолютные u32 границы. Место вставки = source Story TEXT offset + 2 × UTF-16 offset. Предсказание «FD» означает совпадение с хотя бы одним u32 из FDPP или FDPC; сохраняются pp-hit, pc-hit, обе метки, расстояние до ближайшей границы.

После фиксации всех исходных меток инструмент использует оригинальный Writer `Lalalalendia/rar2@703808408fd919e564a90cdc236e81db3c04af8b`, вставляет один ASCII символ, проверяет Reader reopen, семантику остальных Story по SYID и побайтовый EditorProject replay для каждого успешного candidate.

**Главная метрика** — TP/FP/FN/TN для точного отказа `quill_insertion_at_fd_boundary`; остальные Writer guards учитываются отдельно, а не выдаются за успешное сохранение. Единица независимого источника — SHA, а не каждое редактирование. Пустая положительная группа или контрпримеры тоже считаются результатом и публикуются.

## Безопасность и ограничения

В GitHub Actions публикуются только source-safe `plan.json`, `records.json`, `report.json`. Строгий валидатор разрешает только SHA, хост, численные ID/смещения и размеры, булевы индикаторы, safe machine codes, агрегаты и доказательные SHA кандидатов. Сырые файлы PUB, Quill, Story text, URL, журналы запросов, токены и stderr не выводятся. Минимальный научный объём — 10 SHA-verified/Editor-evaluated файлов и 30 Writer arms; иначе научный итог помечается недостаточным.

**Перенос:** только ограниченный preflight сигнал для владельца Writer. Это не закон Microsoft Publisher, не native Publisher Open/SaveAs и не основание снимать защитные проверки. Исходный `rar2` не меняется.
