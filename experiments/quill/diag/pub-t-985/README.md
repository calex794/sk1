# PUB-T-985 — равны ли сырые стили по обе стороны FDPC границ?

Задача: https://app.notion.com/p/3f632a84beec81ba8c92f10f7d77f349

**Новое исследование модели Quill.** PUB-T-976 доказала строгую принадлежность FDPP к концам CR и показала, что FDPC не всегда обрамляет CR. Здесь исследуем то, чего T976 не измеряла: совпадает ли **полная сырая запись символьного стиля** у двух соседних интервалов FDPC, и как это зависит от позиции относительно CR и границы страницы.

Проверяется: повтор исходной записи по тому же physical offset (alias), равная последовательность байтов в двух разных физических позициях, либо различная последовательность байтов. Сравнение происходит только внутри исходного Quill в оперативной памяти; никакие стили/текст/PUB или их байтовые хеши не публикуются. Данные привязаны к SHA каждого источника.

Исходные данные: **ровно 47 SHA** и 37 хостов исторического T971/T976, отобранных при SK1 commit cd38c8d6a545737f9f99821076340505db5e149c. Прежние 178 SHA исключены. Предыдущий T976 архив ZIP SHA-256 14e5c0c04e2ab220f692de8231e252fc34c5af9677662443b870e03f6abf0553. Эти источники не являются независимым новым корпусом по отношению к T976, но вопрос и обработка style payload новые.

Reader/CFB pinned rar2@703808408fd919e564a90cdc236e81db3c04af8b. Не вызывать Writer. Для FDPC используется наблюдаемая грамматика: u16 count, 8B prefix, count*4 absolute UTF16 TEXT ends, count*2 u16 relative style offsets, далее raw style record с префиксом u32 length. Источник физической информации — оригинальные байты, а не результат Writer.

Независимо вычислять CR start/end (отдельно terminal/internal Story). Проверить все соседние FDPC записи по сортировке TEXT end, отделить переходы между дескрипторами, дубли граничных offset и абсолютные физические aliases, сравнить полные raw style records побайтово. Для известных CR позиций разрешено перекрытие классов (два соседних CR), при сравнении считать total union, не сумму категорий.

Безопасный отчёт состоит только из plan.json, records.json, report.json со строго ограниченным полем fdpc_raw_style: числовые счётчики, другие ранее проверенные T976 показатели. Проверка валидатором обязана совпасть с number of fdpc entries/adjacent pairs, равенствами классов и исходным 47-SHA планом. Не меньше 15 разобранных PUB, >1000 FDPC style records.

Даже если соседние записи byte-identical, это не разрешение удалять FDPC границы: BTEC, STSH, UI и native Publisher могут опираться на расположение записей. Результат ограничен исследованным корпусом и исходным Reader, native Publisher не запускался.
