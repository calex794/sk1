# PUB-T-986 — BTEC-ссылки на 16 границ одинаковых FDPC стилей

Исследовательская задача: https://app.notion.com/p/3f632a84beec816dba39f989f3616d69

## Вопрос
В T985 на 31 оригинальном PUB наблюдали 16 границ, где на стыке двух разных FDPC страниц полные сырые bytes соседнего стиля одинаковы. Сохраняются ли эти страницы отдельными физическими BTEC targets и совпадает ли логическая BTEC граница с окончанием предыдущей FDPC страницы?

## Независимая ось данных
- Исходные 47 SHA и 37 хостов **точно те же**, что в T971/T976/T985, отбор pinned SK1 commit cd38c8d6a545737f9f99821076340505db5e149c, без замены недоступных. Из старого [T985 ZIP #11698106274](https://github.com/calex794/sk1/actions/runs/38128991785/artifacts/11698106274), SHA256 2b0dcbeb60ae4d5dbe05648e17231be36858b73a92c75c1eae27825e21eca113, закреплена численная контрольная таблица 31 исходного SHA (`baseline_t985.json`, 798 FDPC страниц / 5406 стилей / 767 стыков / 16 равных). В ней нет сырых стилевых байтов или их хешей.
- Исходный `rar2@703808408fd919e564a90cdc236e81db3c04af8b` используется **только для чтения CFB и каталога**. Ни Writer, ни Publisher, ни локальный Codex не вызываются.
- Доказанная ранее type-4 PLC грамматика BTEC: u32 N, u32 dataSize=4, флаги 4 байта, N+1 логических позиций, N физических смещений target. Не считать прежний синтаксис новой находкой. Все значения читаются с физического исходника и проверяются по границам.
- Каждый BTEC target сопоставляется физическому началу FDPC descriptor. Отдельно учитываются неизвестные targets, страницы без ссылок, страницы с несколькими ссылками, несоответствие logical end последнему FDPC record stop, и ненулевые флаги. Не скрывать случаи без поддерживаемой грамматики (`ABSENT`,`STRUCTURE_BLOCKED`,`PARTIAL`).
- Для каждой исходно равной raw-style page seam сохранять только числовой свидетель: страница, физический target, абсолютная UTF16-граница, индекс BTEC строки, булевы проверки наличия 2 distinct rows и согласования позиции. Ни исходный PUB, ни текст, ни байты/хеши стилевых записей не выгружаются.
- Проверка `check_report.py` независимо пересчитывает сводки, категории BTEC, witnesses и совпадение с заранее закреплёнными числовыми значениями T985 на всех вновь доступных пересекающихся SHA. Обязательное условие научного SUCCESS — >=15 COMPLETE исходников, >=10 из 16 подтверждённых equality seams, >=15 baseline source matches и отсутствие baseline drift; в противном случае результат отмечается PARTIAL, даже если отдельные числовые записи корректны.

**Граница:** одинаковые сырые записи стилей и разные BTEC targets не означают, что Publisher позволяет удалить одну страницу или что стили визуально идентичны. Не изменять rar2 и не придумывать перераспределение страниц.
