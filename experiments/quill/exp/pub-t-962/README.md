# SK1-QUILL-EXP-PUB-T-962 — реальные границы роста текста

**Исследовательская задача:** [PUB-T-962 в Notion](https://app.notion.com/p/3f532a84beec81a090b3f065a34c2c16). Изолированный опыт в SK1, не разработка Writer.

## Новый вопрос
Сколько **положительных ASCII UTF-16 единиц** допускает текущий preservation-first Quill Writer при вставке в одну исходную Story, пока не сработает охрана данных? Насколько близко первая блокировка находится к предыдущей успешной длине на реальных публичных PUB?

Это не повторённый synthetic fixture из RPUB-RUN-189 (+241/+242), и не EXP003–005 (+1 вставка / двухбайтовый защищённый хвост). T959 проверял **удаление** и физические CFB-изменения; T960 — две независимые Story; T961 — разные BMP символы. Здесь одна и та же ASCII вставка меняет только длину.

## Строго закреплённый ввод
- Оригинальный Reader/Writer: Lalalalendia/rar2@703808408fd919e564a90cdc236e81db3c04af8b. Никаких изменений в исходниках продукта.
- Выборка: детерминированные **27 разных исходных SHA**, выбранные из публичного манифеста EXP005 по тем же 7 host-квотам, что и в T959. 35 старых EXP001–004 SHA исключены. Источники не заменять при ошибках загрузки.
- На каждом исходнике первая Editor-eligible Story с ASCII alnum, позиция второго ASCII alnum; все попытки заново исходят от исходного PUB, без цепочки накопленных изменений.
- Вставка: повтор одной ASCII буквы, отличающейся от обоих соседей исходного места. Шкала 1,2,4,...,8192 символов до первого отказа; если есть подтверждённый WRITER_BLOCKED, уточнить границу ограниченным двоичным поиском и проверить соседнюю длину.
- Первый отказ и его reason code — самостоятельное наблюдение. Не называть найденную границу абсолютным математическим максимумом вне проверенных длины/места/Writer.
- Для каждого успешного результата: повторный Reader/Editor open, идентичность остальных Story по SYID, byte-exact replay EditorProject, исходный SHA, размеры Quill/PUB, отсутствие изменений остальных логических CFB-потоков, FAT/MiniFAT/цепочки, хеш кандидата.

## Безопасность данных
В GitHub публикуются только plan.json, records.json, report.json со строго допустимыми полями: SHA, имя публичного хоста, численные длины/смещения, булевы проверки и безопасные коды. Изначальные URL файлов, Story text, сырые Quill/PUB и промежуточные кандидаты остаются в временной папке GitHub Actions и никогда не загружаются как артефакты. stdout/stderr потенциально содержащие исходник не печатаются.

## Приёмка
check_report.py независимо пересчитывает знаменатели, квоты, план опытов, результат каждого arm, сумму PASS/guard и запрет произвольных полей в артефактах. Не меньше пяти реально допущенных исходников для научного итога. Неудачные исходники/неожиданности остаются в сводке, а не замалчиваются. CI success — лишь исполняемый протокол, итоговый научный вердикт требует независимого просмотра ZIP и записи в Notion.

**Не оценивается:** физическое увеличение CFB за пределы текущего Writer, принятие родным Microsoft Publisher, native SaveAs, сохранение внешнего вида/шрифтов, право включать продуктовую кнопку Save.
