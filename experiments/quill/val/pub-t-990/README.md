# PUB-T-990 — BTEC↔FDPC на независимых файлах разных выпусков Publisher

[Каноническая задача в Notion](https://app.notion.com/p/3f632a84beec8132b76be364c41b3508)

## Чем это отличается от T985/T986

В [PUB-T-986](https://app.notion.com/p/3f632a84beec814d8fcbe3e56a745db1) физическая BTEC-адресация подтверждена 798/798 страниц на 31 файле из **старого 47-SHA набора**. На других поколениях и на новых, не пересекающихся SHA такая проверка не выполнялась.

Новая работа использует ровно **66** источников общей длиной **6 176 540** байт, закреплённых в `sources.json` (содержит только Git path + blob SHA1 + size). Источники на трёх независимых внешних GitHub-проектах:

- PRONOM: digital-preservation/pronom-research-week@10d3c0afea0863a7c0acaa01344cb576e9b1ac18, 30.
- Apache POI: apache/poi@c85c6918858ea279de2c33df70518c105064df41, 15.
- libmspub-test: fosnola/libmspub-test@33d8f78db8b8b319098c3d5ba3ad3e952369b323, 21.

Не все файлы содержат Quill: до-Publisher 98 наследие документируется как не применимое, а не как контрпример. Разделение 0x22/0x2C и ревизии берутся **из байтов Contents**, не из названия каталога или метки версии.

## Условия

1. Для каждого публичного исходника строго сверить размер, Git blob SHA1 и вычислить source SHA256. Запретить повторное использование любого SHA256 из прежнего 47-SHA списка, пересчитываемого по закреплённому `SK1@cd38c8d6a545737f9f99821076340505db5e149c`. Внутренние дубликаты источников исключить из числа независимых положительных.
2. Из оригинального CFB прочесть только Contents family/revision и Quill (если имеется). На точном `rar2@703808408fd919e564a90cdc236e81db3c04af8b` выполнить прежний строгий тип-4 PLC физический BTEC→FDPC join. Не менять Writer или существующие оригинальные PUB.
3. Зафиксировать для каждого документа: SHA256, код группы, байтовую семью, ревизию, число страниц, BTEC targets, несовпадения ссылок/позиций, число внутренних и межстраничных совпадений записей стилей. Опубликовать только числовые поля, безопасные коды и SHA. Никаких сырых PUB/Quill/styles/Story-текста/URL загрузок в CI artifact.
4. Оставлять отдельно `NO_QUILL`, `NO_CONTENTS`, `NOT_CFB`, `QUILL_CATALOG_BLOCKED`, `ABSENT`, `PARTIAL` и сетевые ограничения. Полное подтверждение только если **≥15** разных SHA с `COMPLETE`, из них **≥3 семейств 0x22** и **≥3 семейств 0x2C**, минимум два исходных GitHub проекта; иначе `PARTIAL`.
5. Строгий `check_report.py` независимо перепроверяет манифест, статусы, инварианты BTEC/FDPC и статистику по поколениям. После CI изучить ZIP и занести фактические знаменатели в Notion. Инвариант BTEC-адресации ≠ разрешение сливать равные стилевые страницы; native Microsoft Publisher/SaveAs не оценивались.

## Планируемый практический результат

Понять, можно ли применять один алгоритм поиска физических BTEC→FDPC ссылок к старому 0x22 и новому 0x2C Quill или нужны ветви разбора по ревизиям. Даже при полном совпадении нельзя выводить недоказанную native policy выделения страниц.
