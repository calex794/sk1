# SK1-QUILL-VAL-PUB-T-971 — независимая внешняя проверка N→N+1

Каноническая задача: https://app.notion.com/p/3f532a84beec815b9c14f645ee448fa2

## Научный вопрос
Можно ли по исходному PUB, без пробных вызовов Writer вычислить точную границу положительного роста N UTF-16 ASCII и заранее назвать первый код отказа при N+1? Предыдущий T967 доказал 14 совпадений, но все они уже имели измеренные исходы, а T970 обнаружил 347 реальных growth-guard отказов в поисковой фазе +32/+128/+256 на тех же 22 файлах, без точной смежной границы.

## Новый корпус и правило без отбора по Writer
Все 47 ранее неиспользованных SHA исходного фиксированного lalamu@f78cc6f455f4dc222868f9cc035511a6ca7a91ea (370 записей), строго HTTPS .pub без query/fragment, 1–2.5 МБ, начальный SHA-256 и размер. Предварительно исключены 178 разных SHA: 35 EXP001–004, 62 EXP005, 27 T968, 27 T969, 27 T970. Остаток всех 47, 37 разных хостов, суммарно 28 191 744 байта. Ни один недоступный адрес не заменять. Получение входных файлов ограничено четырьмя параллельными подключениями, редирект только на проверенный исходный хост.

## Протокол
На каждом подходящем Editor исходнике выбрать до трёх обычных Story. Для каждой — второй ASCII-символ (second, при одном символе — первый), один фиксированный ASCII маркер. Сначала в режиме только чтения: исходный TOKN Story membership, точное попадание в FDPP/FDPC. Если TOKN или FD, заранее записать более приоритетный защитный класс и проверить только +1.

Для остальных Story до какого-либо Editor.replace/Writer вызова выполнить двоичный поиск только на исходной структурной геометрии: функция classify_growth(n) повторяет охранный порядок текущего pinned Writer, без его вызова и без кандидата PUB. Получить N в [0,8192], заранее закрепить N+1/N+2 safe machine codes. Лишь после фиксации всех source-only прогнозов сделать независимые Writer arms на неизменённом оригинале: +1, N, N+1, N+2 (без повторных доз), при N=0 только +1/+2, при N=8192 только +1/+8192 и правое цензурирование. Любой неожиданный код — контрпример, не повод подбирать длину по ответу.

Каждый PASS проходит Reader/Editor reopen, целевую Story по SYID, все другие Story, точный byte replay EditorProject и исходный source hash. Отказы публикуют только нормализованный machine code. Проверять раздельно число источников, Story, порогов и всех Writer arms, а не называть сотни arms независимыми файлами.

## Критерий
Не менее 10 независимых доступных источников и 10 соседних границ N PASS / N+1 отказ, строгий check_report.py, независимое изучение ZIP/схемы/матрицы и Notion-bound результат. При недостатке данных — INCOMPLETE. Никаких raw PUB, Story text, ссылок на исходники, Quill bytes, stderr, токенов в public artifact; только plan.json, records.json, report.json с source SHA, безопасными числами/кодами и хешами кандидатов.
