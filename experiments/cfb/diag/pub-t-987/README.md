# PUB-T-987 — натуральные границы SYID в 625 PUB

[Каноническая задача в Notion](https://app.notion.com/p/3f632a84beec81e794b3c64c9405e086)

**Новый вопрос:** существует ли среди заранее закреплённых 625 настоящих Publisher PUB экземпляр, у которого исходный Quill SYID first DWORD имеет младший байт 0xFE или 0xFF? Если да — воспроизвести реальную обратную правку Writer на неизменном исходнике и сравнить все байты CFB/PUB.

## Вход и происхождение

Точное закрепление: Lalalalendia/lalamu@87094c23e2a9eaa2aa9e95d72ec52f72ef109f11, дерево pub-corpus/corpus/native/unclassified@8146fa9fdd2f577ebe02bc7205a61bb14e20d3e7, ровно 625 SHA-именованных *.pub. Исходники ранее материально закреплены; эта задача не добавляет 625 новых файлов к корпусу. Каждый SHA повторно вычисляется по исходным байтам. В 625 ранее подтверждены 396 зрелых 0x2c, 228 старых 0x22 и 1 malformed/unknown. 1050 materialized добавляет главным образом старый 0x22 и не увеличивает зрелый Quill 396 набор — повторного двойного счёта нет.

Полный последовательный исходный Quill/SYID census: для каждого из 625 безопасный статус и при успехе первый u32 SYID.header, syid.count, max live SYID и младший байт. Все natural FE/FF исходники проходят дополнительный настоящий Writer; ноль положительных — допустимый ограниченный исход, а не повод менять корпус.

## Истинный Writer, не повторение кода

Контрольный Quill/CFB Reader и Writer — **исходный** Lalalalendia/rar2@703808408fd919e564a90cdc236e81db3c04af8b, исходный эксперимент PUB-T-984@14ac75ae0346b3bdbeeada110e1f463dda6cbb27, он пересобирается из строго закреплённых upstream T963@2caeec283312b0865054ae6f5f93fc9ac1c76b9d и T971@cd38c8d6a545737f9f99821076340505db5e149c. Нет второго Writer и изменений rar2. Никакого искусственного изменения первого DWORD SYID.

На каждом FE/FF источнике используются до трёх исходно подходящих Story в Quill ordinal, второй ASCII-символ, две одиночные Writer операции и две обратные композиции только при допуске обеих исходных операций. Проверка Reader reopen, siblings, byte-equal EditorProject replay и полный абсолютный байтовый diff PUB в точности наследуются от T984. У каждого финала арифметическое ожидание = число различий old/new little-endian u32 при числовом +2; запрещён подбор источников и игнорирование контрпримеров.

## Контроль результатов

Независимый check_report.py заново перечитывает **все 625 исходных PUB**, проверяет источник git tree SHA, точные SHA/размеры каждого исходника и 625/625 JSON, сверяет все FE/FF кандидаты и проверяет истинные Writer/CFB receipts прежним pinned валидатором PUB-T-963. Исходные/конечные PUB, текст, исходные URL и stderr никогда не покидают GitHub worker. Публикуются только plan.json, records.json, report.json и агрегированные безопасные числовые показатели.

Результат положителен лишь для реально допущенных и завершённых Writer-финалов; обнаружение натурального FE/FF без успешной Writer обратимости — отдельная ограниченная находка; отсутствие FE/FF — точный нулевой перепись в закреплённом корпусе, а не универсальный закон Publisher.
