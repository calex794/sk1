# PUB-T-983 — фактическая цена CFB чтения и сохранения

[Исследовательская задача в Notion](https://app.notion.com/p/3f632a84beec819d895dc48dc572a6b5).

**Гипотеза оптимизации, а не форматный закон:** код `pub_cfb::read_stream_reader` использует `read_to_end`, а `replace_stream_reader` удерживает оригинальный CFB, его логические потоки и затем дополнительную копию. Это может создавать высокое потребление памяти даже при редактировании одного потока. Мы измеряем именно это, но не меняем продуктовый код.

## Строгий опыт

- Оригинальный `Lalalalendia/rar2@703808408fd919e564a90cdc236e81db3c04af8b`; копируется только исследовательский двоичный измеритель в временный `examples/` GitHub runner. Все оригинальные исходники без изменений.
- 10 точно названных публичных `.pub` из `apache/poi@ae62bb5116b9aee19ebd5834e3a82066132c9f7f/test-data/publisher`, предварительно фиксированы Git blob SHA1 и ожидаемый размер в `run.py`. Исходники не меняются. Каждая ошибка загрузки/Quill учитывается отдельно, не заменяется другим файлом.
- Для каждого: `inspect_reader`, `read_stream_reader(/Quill/QuillSub/CONTENTS)` и `replace_stream_reader` с **тем же самым** Quill без изменения его байтов.
- Каждый вызов повторён 3 раза; между вызовами заново сбрасываются счётчики временно живых выделений `malloc/realloc/free` Rust, выделенных байтов, обращений Read/Seek и времени.
- Счётчик показывает **дополнительно выделенную память внутри вызова** без заранее загруженного входного файла. Это не пиковая RSS процесса и не гарантия такого же поведения Windows. Для честного сравнения использовать отдельно input size, сумму размеров логических потоков и Quill length.
- Проверка подтверждает равенство логических потоков CFB и повторяемость тождественного результата. Выходной CFB и все сырые данные остаются в закрытой временной памяти runner.

## Проверка и границы

`check_report.py` независимо пересчитывает все измерения и агрегаты по строго ограниченным `plan.json / records.json / report.json` — SHA, размеры, число выделений, их пик, число/объём чтений и времена. Исходные PUB, CFB-потоки, текст и адреса загрузки не попадут в архив. Минимум 8 источников должны пройти успешную проверку.

Этот опыт даст конкретные числа для владельца `rar2`: стоит ли вводить ресурсные ограничения и однопроходное извлечение потоков. Сам по себе он **не доказывает ускорения альтернативного алгоритма** и не требует запускать Microsoft Publisher.
